# 창문·공조·열선이 주행 기록과 만화에 들어가는가 (2026-11-13)

탐침(`../2026-11-12-cartoon-probe`)에서 읽히는 것만 확인했던 창문 위치, 공조 설정 온도·풍량, 운전석 시트 열선을 앱의 주행 기록에 넣고,
가상 콘솔로 실제 주행을 시켜 기록과 이번 화 화면을 확인했다. debug 빌드, Pleos Connect v2.1.0 에뮬레이터.

## 방법

`cabin_drive.py`(저장소 루트에서 실행, `tools/vc.py`를 씀): P단에서 창문 0·온도 22·풍량 3·열선 0 → D단 →
열선 2, 온도 17, 풍량 8, 창문 100 → 75초 → 창문 0 → P단. 끝나고 온도·풍량·열선을 원래 값으로 되돌렸다.

## 결과

새 주행 기록 한 줄(형식 T7, 마지막 네 칸이 이번에 더한 값):

```
T7 | 1794510859988 | 1794510941083 | 0 |  | 0.0 | ? | 0.0 | 0 | 0 | 0 | 0 |  |  | D | 75008 | 17 | 1 | 2
```

- 창문을 전부 연 시간 75,008ms(콘솔에서 75초 열어 둠), 공조 설정 17도, 풍량 최대(1), 열선 2단. 넣은 값과 같다.
- 이번 화(`app-episode.png`): 제목 「창문을 전부 내린 날」, 2컷이 열선 컷(「주인은 운전석 열선을 2단으로 켰다.」, 근거 「운전석 시트 열선 단계」).
  창문(점수 6.0)과 열선(5.5)이 공조 17도(5.0)보다 높아 두 사건으로 뽑혔다.
- 동의 버전 8(`consent-v8.png`): 기록하는 것에 창문을 내리고 달린 시간, 공조 설정 온도와 풍량, 운전석 열선 단계가 들어가 다시 동의를 받는다.
- 새 권한 `CAR_CLIMATE`, `CAR_SEATS`(읽기만)는 설치 때 `granted=true`.

## 확인하지 못한 것

- release 빌드에서의 같은 확인(R8). 동결 뒤 release 재검증 때 같이 본다.
- 공조 전원(켜짐/꺼짐)은 읽지 못한다(탐침에서 좌석 영역 미지원). 그래서 "에어컨 17도"는 설정 온도이고, 실제로 에어컨이 돌았는지는 모른다.
- 창문 값의 방향(0 닫힘)은 안드로이드 표준과 콘솔 기본값으로 판단했고 Pleos 문서에는 없다. 실차 확인 필요.

## 갤러리 확인(열선, 평범한 날의 고비)

debug 갤러리(`CartoonGalleryActivity`)에 16번(열선 2단, 밤)과 17~22번(c8 세션이 더한 고비: 10번째 주행, 함께 500km, 나흘 만의 비,
사흘 만에, 닷새째 같은 시간, 세 번 연속 한 번에)을 넣고 한 화씩 캡처했다(`gallery-16.png`~`gallery-22.png`).
말풍선 꼬리가 차를 가리키고, 글자와 그림이 겹치지 않으며, 밤·해 질 녘·비 배경이 맞게 나왔다. 17~21번의 셋째 컷 주차 그림이
기어 5번인 것은 갤러리 기본값(주차 5번) 때문이고, 실제 기록에서는 그 주행의 값이 나온다.

## 달리다 바꾼 공조(사용자 지시 "추워서 히터를 켰다, 엉뜨를 켰다, 통풍시트를 켰다", 2026-11-13)

- 새 사건: 달리다 공조 온도를 2도 넘게 올림/내림, 출발 때 꺼 둔 열선을 달리다 켬, 통풍시트(달리다 켰거나 일주일 만). 갤러리 23~26번 캡처.
- release(R8) 실주행: 출발 22도·열선 끔 → D단 → 26도, 열선 2 → P단. 이번 화 「달리다 히터 온도를 올린 날」, 2컷 「22°→26°」(근거 공조 설정 온도 출발 22도 → 주차 전 26도),
  3컷 달리다 켠 열선 2단(근거 · 출발 때 꺼짐). `release-heat-up.png`.
- release 성능(앱을 다시 띄우고 60초 기다린 뒤 `vc.py measure 60`, 속도 권한 있음): CPU 코어 1개 기준 3.21%·3.04%(4코어 0.80%·0.76%),

  측정 중 스레드별로는 binder(차량 신호 콜백)가 가장 많았다.
